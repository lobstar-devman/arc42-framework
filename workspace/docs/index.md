# Architecture Documentation

This site is generated from the project's sources of truth (BPMN/CMMN/DMN
XML, Structurizr DSL, OpenAPI, JSON Schema, and Mermaid text). It follows
the [arc42](https://arc42.org) template, with system-structure diagrams
following the [C4 model](https://c4model.com).

**Nothing on this site is hand-edited.** Every page and every diagram is
regenerated by the CI pipeline whenever its source of truth changes. To
change something, edit the source of truth — see
[Sources of Truth](sources-of-truth/index.md) for where each one lives.

## Contents

- [Architecture (arc42)](arc42/01-introduction-and-goals.md) — the full
  arc42-structured architecture description.
- [Sources of Truth](sources-of-truth/index.md) — what format is used for
  what, and where each file lives.

  decision records.

## For implementation agents

If you're implementing against this design in a separate stack, don't
scrape this rendered HTML. Everything here is also served **raw** — the
same paths, unrendered — on port 8001 (e.g. this page is
`GET /docs/index.md`, [Sources of Truth](sources-of-truth/index.md) is
`GET /docs/sources-of-truth/index.md`), alongside every source-of-truth
directory (`processes/`, `architecture/`, `apis/`, `data-model/`,
`data/`) that lives outside `docs/` entirely. `GET /` on that port
redirects straight to `/docs/index.md` (this page) rather than listing
the workspace root. Toolkit-authoring files sitting directly at the
workspace root (`AGENTS.md`, `CLAUDE.md`, `architecting-agent.md`,
`mkdocs.yml`) are not served there — only `docs/` and the
sources-of-truth directories are; those files are how the toolkit is
authored, not part of the architecture you're implementing.

When a page embeds a generated diagram (a `docs/diagrams/**/*.svg`),
don't consume the SVG — it's a rendering. Resolve it to the
source-of-truth file it was generated from using the convention in
[Sources of Truth](sources-of-truth/index.md#resolving-a-diagram-back-to-its-source),
and fetch that instead.
